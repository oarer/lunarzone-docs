## Словарик

| Слово | Что значит простыми словами |
| --- | --- |
| **DoS-атака** | Заваливание сервера огромным числом запросов, чтобы он перестал отвечать |
| **Флуд** | Поток мусорных запросов подряд |
| **IP-адрес** | Числовой адрес компьютера в сети, например `1.1.1.1` |
| **Домен** | Буквенное имя сайта, например `example.com` |
| **Резолвиться** | Превращаться: домен резолвится в IP-адрес сервера |
| **Хостинг / хостер** | Компания, которая сдаёт серверы в аренду (здесь — Aeza) |
| **Abuse-жалоба** | Жалоба хостеру: «с вашего сервера идёт атака, примите меры» |
| **Тикет** | Обращение в поддержку с номером, по нему отслеживают ответ |
| **Backend** | Серверная часть сайта, которая обрабатывает запросы |
| **БД** | База данных, где хранятся пользователи, сборки и т.д. |
| **API / ручка** | Адрес, по которому программа обращается к серверу, например `/api/v1/users/` |
| **`%RAND%`** | Случайная строка: атакующие перебирали несуществующие ID пользователей |
| **Коды 200 / 404 / 422 / 499 / 502** | Ответы сервера: 200 — всё ок, 404 — не найдено, 422 — неверные данные, 499 — соединение оборвано, 502 — сервер не справился |
| **UA (User-Agent)** | Подпись программы, делающей запрос (браузер, скрипт и т.п.) |
| **Лог** | Текстовый журнал: кто, когда и что запрашивал у сервера |
| **Хэш (sha256)** | Контрольная сумма файла: фиксирует, что файл не менялся с момента подсчёта |
| **Телеметрия / sysstat** | Статистика нагрузки сервера, которую собирает сам сервер |
| **Парсинг** | Автоматическое копирование чужого контента к себе |

## 3. Поведение mamoru

### 3.1 Отказ от прямых утверждений

Стандартная формула: `не утверждаю, доказательств нет, без них никого не обвиняю`.
Даже связку `сообщение 08.09 + нагрузка в те же дни` подает как фиксацию двух фактов без выводов. Формально обвинение отсутствует, но сопоставление сохраняется в споре.

### 3.2 Контроль рамки через поправки

Вход в очный разбор: `почти верно, две поправки`:

- ответ хостинга о варне никто не показывал, это заявление, а не документ;
- пункт об обвинении записан неверно.

Параллельно выстраивается иерархия доказательств: оригиналы sysstat с хешами от 24.08 и тикет №47197 против скриншота и текстового файла с хешем от 21.09.

### 3.3 Смена тем

- Вопрос синхронной работы `81 + 62` → обсуждение кодов `401/422` по `/auth`.
- Вопрос сессии `81 = MamoruFX` → обсуждение даты 26.08 и какая карточка открыта.
- Вопрос сборок и `server-monitor` → обсуждение состава лог-строки и подделываемости UA.
- Вопрос `.eml` → обсуждение разницы формулировок жалобы и чата.

Синхронный старт второго адреса в 17:50:56 по существу не разбирается.

Насчёт кодов:

> `С 81.163.133.244 POST /api/v1/auth/refresh отдает 422 восемнадцать раз, с 17:41 по 17:47. Для сравнения, в том же файле на той же ручке: 66.249.73.96, это робот Google, получает тот же самый 422. А 5.16.126.146 получает 200, три раза, в том числе в 17:48:33, в самый разгар. То есть ручка в это время работала и отвечала по-разному. Донецкий адрес получал от нее ровно то же, что поисковый робот`

Роут: [/src/app/api/auth/index.ts](https://github.com/oarer/stalhub_backend/blob/main/src/app/api/auth/index.ts), строка 240.
Код 200 — значит клиент успешно обменялся токенами, 422 — значит то что у клиента нет токенов и обмен не происходит.
